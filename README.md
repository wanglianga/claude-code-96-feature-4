# 仁和医院 · 日间手术患者陪诊交接与术后接送平台

## 原始需求

> 设计医院日间手术患者陪诊交接与术后接送页面，可使用 React、TypeScript 和 Zustand。患者到院签到后，页面展示手术类型、禁食时间、过敏史、术前检查、缴费状态、陪诊人、接送人和预计手术顺序。护士在术前评估区录入生命体征、皮试结果、知情同意、随身物品封存和是否需要绿色通道，信息会影响候诊区排序和手术间准备。患者进入手术区时，陪诊人需要在页面确认交接时间、物品袋编号和术后联系号码；手术等待期间，家属看到的是经过脱敏的状态节点，例如已入室、手术中、复苏观察、待接走。若患者临时血压异常、手术延迟、麻醉方式改变、陪诊人离院、接送人更换或费用未结清，页面把护士、麻醉医生、收费窗口、家属和接送人放在同一条手术记录里推进。患者离院前，护士确认疼痛评分、饮水进食、排尿情况、用药说明和复诊时间，接送人签收后，页面生成术后注意事项和异常回访任务。页面还要适配手术区、候诊区和家属端的不同信息展示边界，护士可以看到完整病情和护理动作，家属只能看到经过解释的状态进度。若患者在复苏室滞留时间过长，页面应提示是否因为疼痛、恶心、无人接送或医生仍需观察，并把该原因带入当天手术周转统计。

## 技术栈

- React 18 + TypeScript + Zustand（状态管理，单一手术记录 store 驱动全部角色视图）
- Vite 5 构建，纯前端 SPA（演示数据内置，无需数据库等依赖服务）
- 生产运行：多阶段 Dockerfile → 非 root `nginxinc/nginx-unprivileged`（容器内 8080 端口）+ HEALTHCHECK

## 一键启动（Docker）

```bash
cp .env.example .env        # 可选；验证环境已注入 CC_PUBLISH_PORT / COMPOSE_PROJECT_NAME
docker compose up -d --build
docker compose port app 8080   # 查看宿主机实际映射端口（例如 0.0.0.0:3096）
# 浏览器访问 http://localhost:<映射端口>
docker compose down           # 验证完毕释放资源
```

验证方式：以「宿主机执行 `docker compose up -d` 后容器健康（healthy）+ 浏览器/接口走通关键业务流」为通过标准。健康检查接口：`GET /healthz` 返回 `ok`。

## 演示数据与推荐演示路径

内置 7 名患者覆盖全部状态节点：待签到(赵磊)、已签到(王建国/李秀兰)、手术中(张伟)、复苏观察(陈丽华)、待接走(刘洋)、已离院(孙桂芳)。页面顶部为**模拟时钟**（2026-09-18 10:30 起），`+15/+30分钟` 用于触发时间相关规则（如复苏滞留）。

1. **签到**：nurse01 → 候诊区看板 → 赵磊「到院签到」；看板展示手术类型/禁食/过敏/检查/缴费/陪诊人/接送人/预计手术顺序。
2. **术前评估**：nurse01 → 术前评估区 → 王建国：录入生命体征、皮试、勾选知情同意、物品封存（物品袋编号）、绿色通道 → 保存后进入候诊排序（绿色通道置顶）。
3. **交接确认**：family01 登录 → 「交接确认」卡片确认交接时间/物品袋编号/术后联系号码。
4. **入室流转**：nurse01 → 手术区 → 王建国「送入手术间」（未结清费用/未签同意书/未交接会被拦截并提示原因，如李秀兰）。
5. **异常同记录推进**：anes01 对张伟登记「麻醉方式改变」「血压异常」；nurse01 可登记「手术延迟」；cash01 为李秀兰结清费用；family 端可登记「陪诊人离院」「更换接送人」——全部落在同一条手术记录时间线上。
6. **复苏滞留**：点头部时钟 `+30分钟` → nurse01 → 复苏室 → 陈丽华超 60 分钟提示登记滞留原因（疼痛/恶心呕吐/无人接送/医生仍需观察），原因自动进入周转统计。
7. **离院签收**：nurse01 → 离院管理 → 陈丽华录入疼痛评分/饮水进食/排尿/用药说明/复诊时间 → family03 签收 → 自动生成术后注意事项与异常回访任务（family04 可直接对刘洋演示签收）。
8. **周转统计**：nurse01 → 周转统计，查看到院/在术/复苏/离院数、平均复苏时长、平均周转时长、复苏滞留原因分布、异常事件分布与回访任务闭环。

## 信息展示边界

- **护士端**：完整病情（生命体征、过敏史、皮试）、全部护理动作与异常事件处理。
- **麻醉医生端**：手术区患者与麻醉相关动作，无收费/离院权限。
- **收费窗口端**：仅姓名/术式/费用，不展示病情细节。
- **家属端**：仅脱敏状态节点（已签到→候诊中→已入室→手术中→复苏观察→待接走→已离院）与经过解释的公告文案；异常事件以安抚性说明呈现，不暴露医疗细节。

## 目录结构

```
├── Dockerfile            # 多阶段：node 构建 → 非 root nginx 运行 + HEALTHCHECK
├── docker-compose.yml    # 仅 app 服务，端口 ${CC_PUBLISH_PORT}:8080
├── nginx.conf            # SPA 回退 + /healthz
├── .env.example
└── src/
    ├── types.ts          # 领域模型（患者状态机/评估/交接/异常/复苏/离院）
    ├── store.ts          # Zustand：全部业务动作与状态机守卫
    ├── data.ts           # 演示账号与种子患者
    ├── utils.ts          # 排序/拦截规则/注意事项生成/周转统计
    ├── components/       # 登录、头部、公共组件
    └── views/            # 候诊看板/术前评估/手术区/复苏室/离院/统计/家属端/收费端
```
